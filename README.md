# Lobotomy Modern Engine (LME) v0.8.6

**Lobotomy Corporation** の長時間プレイ時のメモリリーク（クラッシュ）・後半日数のフレームレート低下・バニラ固有のバグ群・移動カクつき・Spineアニメコマ落ち・音声読み込みスタッターをまとめて解決する統合エンジン改善MODです。

---

## 📦 配布パッケージの選び方（あり版 / なし版）

GitHub の **Releases** にて、用途に合わせて **2つのエディション（あり版 / なし版）** を用意しています。

| パッケージ名 | デバッグ・育成緩和機能<br>（1LOB強化・初期装備無双） | おすすめの対象者 |
| :--- | :---: | :--- |
| **なし版（Standard Edition）**<br>`LobotomyModernEngine_v0.8.6_Standard_*.zip` | **OFF（無効）** | **【通常のプレイヤー向け】**<br>バニラのゲームバランスを一切崩さず、**軽量化・滑らか移動補間・60FPSアニメ・音声事前ロード・バニラバグ修正・文字サイズ改善のみ** を適用したい方 |
| **あり版（DebugPlus Edition）**<br>`LobotomyModernEngine_v0.8.6_DebugPlus_*.zip` | **ON（有効）** | **【周回・検証・時短プレイ向け】**<br>上記すべての改善に加え、**「職員ステータス強化コスト一律 1 LOB」「初期装備（警棒・スーツ）＆懺悔E.G.Oの1撃鎮圧・無敵化」** が最初から有効になっている版 |

> 💡 **補足**: 「なし版（Standard）」と「あり版（DebugPlus）」の中身のプログラムは共通であり、ゲーム画面左上の **ステータスバッジ** または **`F9` 診断画面**（および **`F8` キー**、もしくは `BepInEx/config/com.isaka.lobotonymodernengine.cfg`）からいつでも個別に ON / OFF を切り替えられます。

さらに各エディションには、環境に合わせて以下の2種類があります：
- **`_FullBepInEx.zip`（BepInEx本体同梱フルセット）**: バニラ環境にそのまま解凍するだけで導入完了する初心者向けフルパック。
- **`_PluginOnly.zip`（プラグイン単体版）**: すでに BepInEx 5.x を導入済みの方向け（`BepInEx/plugins/` と `config/` のみ）。

## 🚀 導入方法

### A. フルセット版（`_FullBepInEx.zip`）を使う場合
1. Steam のライブラリで『Lobotomy Corporation』を右クリック → **「管理」＞「ローカルファイルを閲覧」** を開きます。
2. `LobotomyCorp.exe` があるフォルダに、ZIPの中身（`BepInEx` フォルダ、`winhttp.dll`、`doorstop_config.ini`）をすべてドラッグ＆ドロップして上書き展開します。
3. ゲームを起動すると自動適用され、画面左上に **`● LME v0.7.6 [42モジュール適用済 / 71メソッドフック済]`** バッジが表示されます（クリックまたは **`F9` キー** でリアルタイム診断モニターが開きます）。

### B. プラグイン単体版（`_PluginOnly.zip`）を使う場合
1. 導入済みの `BepInEx` フォルダに ZIP 内の `BepInEx` フォルダを上書きコピーしてください。

### アンインストール方法
- `BepInEx/plugins/LobotomyModernEngine.dll` を削除（フルセット導入時は `winhttp.dll` を削除）するだけで、いつでも完全に元のバニラ状態に戻ります。

## 🔧 仕組み解説 ＆ 技術監査に基づく安全設計（v0.7.6 硬化仕様）

### 1. メモリリーク根絶・CPU負荷軽減の仕組み

1. **① 生存参照検証付きシーン遷移リソース解放 (`SpineAtlasCachePatch`, `CursorLeakPatch`)**
   - **安全な破棄タイミングと実参照チェック**:
     - Unity の `SceneManager.sceneLoaded` イベントは「新シーンの読み込み」を通知するものであり、旧シーンの GameObject 破棄完了や `DontDestroyOnLoad` で残存する共通オブジェクトの破棄を保証するものではありません。
     - そのため v0.7.6 では、シーンロード直後に即座に全破棄するのではなく、**1フレーム遅延（`yield return null`）コルーチンで旧シーンの完全消滅を待機** します。
     - さらに、シーン内の全 `Renderer`（メッシュ／Spine）および `Graphic`（UI）をスキャンし、**生存中のコンポーネントが現在も参照しているマテリアル・テクスチャはキャッシュに保持（破棄保留: Retained）し、誰からも参照されていない孤立リソースのみを `UnityEngine.Object.Destroy` で安全に完全解放** します。
     - これにより、シーンまたぎのオブジェクトやDontDestroyOnLoadが存在しても、ピンク抜けやMissingReferenceExceptionが絶対に発生しない完全な安全性を確立しています。

2. **② UI・ポートレートのDirtyフラグ方式＆実測Stopwatchプロファイラ (`WorkerPortraitPatch`)**
   - **状態変化の追跡と負荷の可視化**:
     - 生存/死亡/パニック、装備（武器/防具）、E.G.Oギフト（取得/置換/表示切替）、顔パーツ・髪色・瞳色、所属部門・勤続腕章などの表示パラメータを網羅したハッシュを算出して差分更新を行います。
     - **実測プロファイラの拡充**:
       - ハッシュ監視自体の処理負荷を `Stopwatch` でマイクロ秒単位で精密計測。
       - 理論上の目標値ではなく、**「最終値 (Last μs)」「累積平均値 (Avg μs)」「最大ピーク値 (Max μs)」「総測定回数 (Sample Count)」** をリアルタイムにモニターへ出力。
       - 職員数が50名以上・ギフト多数となる後半日数でも、監視オーバーヘッドの瞬間スパイクが発生していないかを客観的数値で検証できます。

3. **③ `GetAgentList()` 等のキャッシュ化 (`WorkerListCachePatch`)**
   - バニラ元実装自体が `ReadOnlyCollection<T>` を返している不変ビュー設計であることを確認し、内部リスト差し替え時のみラッパーを再生成する安全なゼロアロケーションキャッシュを採用しています。

4. **④ `TakeDamage` IL Transpiler の実命令列検証 (`TakeDamagePatch`)**
   - `WorkerModel.TakeDamage` および `TakeDamageWithoutEffect` 内の計8箇所の `List<BarrierBuf>::ToArray()` 呼び出しを静的スナップショット取得メソッドへ安全に置換し、バリア0枚時のヒープ確保をゼロ化しています。

## 🖥️ ゲーム内診断表示の集計単位と表記仕様 (v0.7.6)

- **ミニステータスバッジ**:
  - `● LME v0.7.6 [42モジュール適用済 / 71メソッドフック済] | 60 FPS | 1-LOB:ON | 神装備:ON [F9:詳細]`
  - Harmonyによる静的なパッチ適用状態を「42モジュール適用済 / 71メソッドフック済」と明記し、実行時の機能正常性と混同しない正確な表記を採用しています。
- **`F9` 詳細モニター**:
  - **パッチ適用状態**: `[42/42 機能モジュール適用済 / 計71 メソッドフック済]`
  - **IL Transpiler**: `[置換検証済] (WorkerModel被弾処理 8/8箇所置換済)`
  - **実行時実測メトリクス**: 実ゲーム内でイベントを検知・処理した項目を `[実働確認済]` とラベル付けし、実測カウンタ（再利用回数、解放数、破棄保留数、Dirtyスキップ数、実測ハッシュ負荷 Last/Avg/Max μs など）を正確に表示します。
- **`F8` キー**: デバッグ初期装備＆懺悔強化の即時 ON / OFF 切り替え
