# Lobotomy Modern Engine (LME) v0.7.5

**Lobotomy Corporation** の長時間プレイ時のメモリリーク（クラッシュ）・後半日数のフレームレート低下・バニラ固有の9大バグ・図鑑／ギフト欄の文字縮小問題をまとめて解決する統合エンジン改善MODです。

---

## 📦 配布パッケージの選び方（あり版 / なし版）

GitHub の **Releases**（または `dist/` フォルダ）にて、用途に合わせて **2つのエディション（あり版 / なし版）** を用意しています。

| パッケージ名 | デバッグ・育成緩和機能<br>（1LOB強化・初期装備無双） | おすすめの対象者 |
| :--- | :---: | :--- |
| **なし版（Standard Edition）**<br>`LobotomyModernEngine_v0.7.5_Standard_*.zip` | **OFF（無効）** | **【通常のプレイヤー向け】**<br>バニラのゲームバランスを一切崩さず、**軽量化・メモリリーク修正・バニラ9大バグ修正・図鑑/ギフト文字サイズ改善のみ** を適用したい方 |
| **あり版（DebugPlus Edition）**<br>`LobotomyModernEngine_v0.7.5_DebugPlus_*.zip` | **ON（有効）** | **【周回・検証・時短プレイ向け】**<br>上記すべての改善に加え、**「職員ステータス強化コスト一律 1 LOB」「初期装備（警棒・スーツ）＆懺悔E.G.Oの1撃鎮圧・無敵化」** が最初から有効になっている版 |

> 💡 **補足**: 「なし版（Standard）」と「あり版（DebugPlus）」の中身のプログラムは共通であり、ゲーム画面左上の **稼働ステータスバッジ** または **`F9` 診断画面**（および **`F8` キー**、もしくは `BepInEx/config/com.isaka.lobotonymodernengine.cfg`）からいつでも個別に ON / OFF を切り替えられます。

さらに各エディションには、環境に合わせて以下の2種類があります：
- **`_FullBepInEx.zip`（BepInEx本体同梱フルセット）**: バニラ環境にそのまま解凍するだけで導入完了する初心者向けフルパック。
- **`_PluginOnly.zip`（プラグイン単体版）**: すでに BepInEx 5.x を導入済みの方向け（`BepInEx/plugins/` と `config/` のみ）。

## 🚀 導入方法

### A. フルセット版（`_FullBepInEx.zip`）を使う場合
1. Steam のライブラリで『Lobotomy Corporation』を右クリック → **「管理」＞「ローカルファイルを閲覧」** を開きます。
2. `LobotomyCorp.exe` があるフォルダに、ZIPの中身（`BepInEx` フォルダ、`winhttp.dll`、`doorstop_config.ini`）をすべてドラッグ＆ドロップして上書き展開します。
3. ゲームを起動すると自動適用され、画面左上に **`● LME v0.7.5 稼働中 (42モジュール正常 / 71メソッドフック済)`** バッジが表示されます（クリックまたは **`F9` キー** でリアルタイム診断モニターが開きます）。

### B. プラグイン単体版（`_PluginOnly.zip`）を使う場合
1. 導入済みの `BepInEx` フォルダに ZIP 内の `BepInEx` フォルダを上書きコピーしてください。

### アンインストール方法
- `BepInEx/plugins/LobotomyModernEngine.dll` を削除（フルセット導入時は `winhttp.dll` を削除）するだけで、いつでも完全に元のバニラ状態に戻ります。

## 🔧 仕組み解説 ＆ 技術監査に基づく安全設計（v0.7.5 硬化仕様）

### 1. メモリリーク根絶・CPU負荷軽減の仕組み

1. **① Spineアトラス＆照準テクスチャの安全なライフサイクル管理 (`SpineAtlasCachePatch`, `CursorLeakPatch`)**
   - **安全な破棄タイミングの設計**:
     - プレイ中（同一日・同一シーン中）にキャッシュを強制破棄（Destroy）してしまうと、ゲーム側のSpineスケルトンや描画メッシュが現役で使用中だった場合に MissingReferenceException やテクスチャ抜け（ピンク表示）を引き起こす危険があります。
     - そのため、**プレイ中は一度生成したキャッシュを安全に再利用し続け、プレイ途中のDestroyは一切行いません**。
     - 職員のSpineコンポーネントが確実に破棄・アンロードされる **「1日の終了（DayEndScene）」「タイトル復帰」「チェックポイントロード」のシーン遷移時（`SceneManager.sceneLoaded`）にのみ、安全に `ClearAllAndDestroy` を実行してネイティブメモリを一括解放** します。
2. **② UI・ポートレートのDirtyフラグ方式＆監視オーバーヘッド計測 (`WorkerPortraitPatch`)**
   - **状態変化の追跡と負荷の可視化**:
     - 生存/死亡/パニック、装備（武器/防具）、E.G.Oギフト（取得/置換/表示切替）、顔パーツ・髪色・瞳色、所属部門・勤続腕章などの表示パラメータをハッシュ化して差分更新を行います。
     - ハッシュ計算自体の処理時間（Stopwatch計測）を `AvgHashCalcMicroseconds` としてモニターに表示し、監視オーバーヘッドがバニラの毎フレームImage/Sprite再構築コスト（数ミリ秒）に対して極めて軽量（数マイクロ秒オーダー）であることを数値で証明・検証できるようにしています。
3. **③ `GetAgentList()` 等のキャッシュ化 (`WorkerListCachePatch`)**
   - バニラ元実装自体が `ReadOnlyCollection<T>` を返している不変ビュー設計であることを確認し、内部リスト差し替え時のみラッパーを再生成する安全なゼロアロケーションキャッシュを採用しています。
4. **④ `TakeDamage` IL Transpiler の実命令列検証 (`TakeDamagePatch`)**
   - `WorkerModel.TakeDamage` および `TakeDamageWithoutEffect` 内の計8箇所の `List<BarrierBuf>::ToArray()` 呼び出しを静的スナップショット取得メソッドへ安全に置換し、バリア0枚時のヒープ確保をゼロ化しています。
